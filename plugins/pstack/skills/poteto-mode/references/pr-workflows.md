# PR workflows on Claude Code and Codex

Apply this reference to native PR creation, Babysit, both autopilots, and Shipping. Other harnesses retain their inherited procedures. Keep Lauren's lifecycle and independent live proof, the [autonomy contract](autonomy.md), and the existing [merge/restack guards](merge-safety.md). This reference connects those steps to native tools; it grants no landing authority.

## Pin the run before the first PR operation

Resolve the installed plugin, actual target worktree, Git root, origin repository, default branch, and requested destination. Read the target's native instructions and task grant. Keep the installed source identity in the run's evidence using the [delegation contract](delegation.md). Run bundled helpers by their installed absolute paths; resolve project checks and the [live driver](verification.md) from the target checkout. A developer checkout or a second cached plugin version is not the installed source.

Choose the forge once. Use the native PR tool for operations it owns when available, with the resolved forge for the rest. Keep GitHub watcher/shipping commands on GitHub. Origin remains optional; before an Origin merge it must prove the equivalent service-enforced head condition and validated pending-request inspection/cancellation. Otherwise deliver merge-ready with that limitation. An available Origin executable alone does not establish equivalent shipping safety.

Confirm the writer can create Git locks and objects in the worktree's shared Git directory; a writable checkout alone does not grant that access. If the host requires a permission grant, request it through its native mechanism and keep a denied write blocked.

Use the native account's existing authentication. Missing permissions are a blocker for the affected operation; do not copy credentials, start a login/browser flow without the user's request, or change global signing to make a test pass. A disposable integration fixture declares its own repository, grants, branch rules and cleanup before creation. For this personal fork, record its URL and leave GitHub repository cleanup to the user; never request repository-deletion access. It never relaxes another repository's gates or invents a required approval from the author's own account.

## Keep the lifecycle boundaries

| Stage                | Evidence and boundary                                                                                                                                                                                                                                                               |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Open                 | Correct repository, head and base; ready PR; URL read back. An open PR does not grant babysitting or merging.                                                                                                                                                                       |
| Babysit              | Explicit mode and frontier. Read the installed watcher's JSON verdict and revision. `--status-only` exit 0 means the status was read, not that checks passed or landing is authorized. Classify a failure and fix its actual owning branch; report topology work to its owner.      |
| Independently verify | A fresh reviewer that did not author the patch drives the required real surface. Keep its native identity, exact head/base/branch, patch-id and receipts. Author self-proof, green CI and a comment that merely says PASS cannot replace it. Follow existing model-diversity gates. |
| Autopilot-full       | A current user grant may authorize the owner to land its named item after the root's independent verdict and every gate. Preserve a joint-review gate or item reserved to the user.                                                                                                 |
| Autopilot-stack      | The root owns topology; owners report STACK-READY. Delivery stops for the operator. A full-autopilot grant for other work does not grant stack landing.                                                                                                                             |
| Ship                 | Re-read authority, revision, pending requests, repository gates and destination immediately before the service-guarded merge. Read back actual merged state, then fetch and confirm the merge commit and expected content in the intended destination before advancing.             |

A PR number is repository-scoped. Carry the repository explicitly through helper calls, comments, checks and merge operations. A base move invalidates the old landing record even when the head is unchanged. A matching patch-id preserves only eligible proof after destination/dependency applicability is checked; CI still needs the current revision. Save a changed record as new evidence, rather than replacing a rejected record to conceal drift.

## Run the native helper process correctly

Claude Code uses its exposed shell/background task tools. Codex may expose shell tools directly or through code mode. Preserve the returned process/session handle and poll it with the matching native tool until an actual terminal result. A yielded command is still running; starting a second watcher or reading an empty output file is not its result. In code mode retain the whole execution result when it contains the handle, rather than forwarding only its output text.

Use the existing watcher for bounded foreground checks and verdict classification. A foreground process, a sleep loop or a retained session handle is not durable scheduling. If the host cannot provide the requested unattended wakeups, report that capability gap and retain an explicit checkpoint; scheduling/recovery work is separate from this PR workflow.

Before rewriting or retargeting any affected link, save `ship-pr inspect` output and require `ship-pr cancel-pending` to return exit 0 with `kind: cancelled` for that exact revision. Follow the existing old-parent boundary and explicit remote-lease recipe. Neither helper grants authority or performs a merge. Queue admission and auto-merge requests remain pending until actual landing is confirmed. Preserve repository-required proofs for the revision that will eventually land.

## Resume or stop without duplicating a landing

On resume after interruption, read the retained run, grant, verdicts and operation records, then inspect the actual PR and destination before retrying a write. Reconcile native worker/process ownership separately. If the PR already merged, verify its final head, base, merge commit and destination content and record that fact; do not merge the next link until the previous result is confirmed. Unknown or contradictory state remains unconfirmed.

On a user stop, send zero-writes orders, stop the owned watcher/tasks, cancel pending requests under the existing safety procedure, and read their state back. Report writes already completed. An interrupted local process alone does not cancel GitHub auto-merge or queue membership. Stop acknowledgement and reconciled remote state precede a replacement writer or resumed landing.

Keep a concise trail of source identity, actual grant/gates, PR URLs, revisions, native reviewer IDs, commands/results, pending-request readbacks, topology boundaries/leases, and confirmed destination commits. Use the task's existing evidence location and [native history](history.md); no new user-global configuration or receipt service is required.
